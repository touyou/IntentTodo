# 公開前に 1.0.0 を取り下げて 1.1.0 を出し直した件

[App Schema 適合](2026-09-12-create-update-schema-adoption.md)で `AddTodoIntent` /
`UpdateTodoIntent` のパラメータを作り直した。その直後に「**リリース済み環境だと大丈夫なのか**」と
聞かれ、Apple の指示（公開済み Intent の形は変えない）に照らすと**公開前に確定させるのが
一番安い**と分かったので、審査に出していた 1.0.0 を 3 プラットフォームとも取り下げて
1.1.0 として出し直した。

## 1. 取り下げ前の状態はプラットフォームごとに違った

`asc versions list --app 6788623037`:

| platform | version | state |
|---|---|---|
| IOS | 1.0.0 | **`PENDING_APPLE_RELEASE`**（審査通過済み / OS 公開待ち） |
| VISION_OS | 1.0.0 | **`PENDING_APPLE_RELEASE`** |
| MAC_OS | 1.0.0 | `WAITING_FOR_REVIEW` |

iOS / visionOS は「審査待ち」ではなく**もう承認されていた**。`minOsVersion` が 27.0 なので
iOS 27 の公開を待つ形で止まっていた。**公開はされていない**ので、保存済みショートカットを
持つ利用者はまだ存在しない — ここが「今なら作り直してよい」の根拠。

## 2. 新しいバージョンは作れない

```
$ asc versions create --app 6788623037 --version 1.1.0 --platform IOS
Error: versions create: The provided entity includes a relationship with an invalid value:
You cannot create a new version of the App in the current state.
```

**in-flight なバージョンがあると次を作れない**（承認済み・公開待ちも in-flight）。
取り下げるしかない。

## 3. 取った手順（3 プラットフォーム同じ）

```bash
# 1. 取り下げ。承認済み(PENDING_APPLE_RELEASE)でも同じコマンドで通り、
#    version の state は DEVELOPER_REJECTED になる
asc submit cancel --version-id <VERSION_ID> --app 6788623037 --confirm

# 2. 新レコードを作らず、同じレコードを改名する（説明文・キーワードがそのまま残る）
asc versions update --version-id <VERSION_ID> --version 1.1.0

# 3. 新しいビルドを付ける → state は PREPARE_FOR_SUBMISSION に戻る
asc versions attach-build --version-id <VERSION_ID> --build-id <BUILD_ID>

# 4. 提出
asc review submit --app 6788623037 --version-id=<VERSION_ID> --build-id=<BUILD_ID> --confirm
```

- **`versions create` は要らない**。取り下げたレコードを改名するほうが、メタデータの
  作り直しが無くて速い（`--copy-metadata-from` も不要）
- `asc` のフラグは `--version-id=<ID>` の形で渡す。`--version-id <ID>` はサブコマンドによって
  `flag needs an argument` になる
- ビルドは `production` へ main を fast-forward して Xcode Cloud に作らせた
  （run #34 / commit 1e0deae → 3 プラットフォーム分の build 34 が VALID）

## 4. `whatsNew` は初回リリースでは編集できない

`metadata/*/version/1.1.0/` に `whatsNew` を書いて apply したら、2 ロケールとも失敗した:

```
The request cannot be fulfilled because of the state of another resource.:
Attribute 'whatsNew' cannot be edited at this time
```

**リリース済みの前バージョンが無いと「このバージョンの新機能」は持てない**。1.1.0 という
番号でも、実際には初回リリースなので同じ扱いになる。`asc validate` では
`metadata.required.whats_new`（severity: warning / blocking: false）として出るだけなので
提出は通る。書いた文章は次のバージョンで使うため `metadata/` からは外した。

## 5. 結果

`asc validate` は 3 バージョンとも **errors 0 / blocking 0**（warning 4 = whatsNew 2 件 +
subtitle + keywords）。1.0.0 のときに 2 回弾かれた Web UI 限定の 2 項目
（App プライバシーの公開 / visionOS の `hasHighMotionLabel`）は、**一度答えると次の提出でも
効いている**ので今回は素通りした。

| platform | version | build | state |
|---|---|---|---|
| IOS | 1.1.0 | 34 | `WAITING_FOR_REVIEW` |
| MAC_OS | 1.1.0 | 34 | `WAITING_FOR_REVIEW` |
| VISION_OS | 1.1.0 | 34 | `WAITING_FOR_REVIEW` |

つまり**最初に公開されるのは 1.1.0**で、`.reminders.createReminder` /
`.reminders.updateReminder` に適合した形が最初から出る。1.0.0 の承認は捨てた
（iOS / visionOS は再審査になる）。

以後は Apple の手順に従う: 公開済み Intent の形は変えず、スキーマ要求と合わないときは
別 Intent + `isAssistantOnly = true` で移行する。
