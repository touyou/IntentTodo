# 開発ログ: コードコメントを英語に統一し、必要な情報だけに絞った（2026-08-31）

## きっかけ

同日のドキュメント整理（[2026-08-31-docs-refine.md](2026-08-31-docs-refine.md)）と同じ切り分けを
コードにも適用した。着手前の状態:

| 項目 | 数 |
|---|---:|
| Swift ファイル | 187 |
| 総行数 | 22,169 |
| `//` で始まる行 | 4,181（**全体の 19%**） |
| うち日本語を含む行 | 1,529（134 ファイル） |
| `docs/` へのリンクを含むコメント | 68 |

方針として決めたこと:

- **英語に統一する**。App Intents 中心設計の参考実装として公開しているので、コードを読むのは
  日本語話者に限らない。ドキュメントは日本語のまま（読者が違う）
- **ドキュメントへのリンクを置かない**。`詳細: docs/insights/...` / `経緯: docs/devlog/...` は
  ①実装中に開かない ②リンク先が動くと黙って腐る ③同じ説明が 2 か所にある状態を招く
- **実装中・コードリーディング中に本当に必要な情報だけ**にする。履歴・将来の計画・コードの言い換えは削る

## やったこと

### 機械的に処理できた分

- 定型の `/// 書き込み系。Extension プロセスが SwiftData を書かないよう…（WWDC 2026 #345）` を
  英語 1 行へ（9 箇所）
- ポインタだけの行（`/// 詳細: docs/...` / `// 経緯: docs/...`）を削除（49 行）+ 行末に付いていた分（4 行）
- 4 パッケージで同文だった `Localization.swift` の `.copy(_:)` 解説を一括置換

### 残りは全部手で書き換えた

1,400 行以上を、意味を保ったまま英語へ。同時に次を落とした:

| 落としたもの | 例 |
|---|---|
| 履歴 | 「旧実装は body 評価のたびに `[String]` を再アロケートしていた」「2026-08-12 に切り替えた」 |
| 将来の計画 | 「Siri 経由の追加 UI が必要になったら `.foreground(.dynamic)` を足す」 |
| 調査の分量に見合わせた長さ | `TodoAppEntity` 冒頭の「なぜ 2 系統なのか」20 行 → 14 行（結論と機械的な理由だけ） |
| コードの言い換え | `// WWDC 2026 で AddTodoIntent / TodoItem に追加した属性の入力。` |
| ファイルヘッダの Xcode 定型 | `// Created by <名前> on <日付>.`（2 ファイルだけに残っていた） |

**残したもの**: 「自明な書き方をすると壊れる」理由。たとえば

- `@DeferredProperty` にしている理由（削除済みオブジェクトの配列属性を読むと trap する）
- `ModelContext(container)` を渡す理由（`mainContext` はコンテナを retain しない）
- `activate()` を使う理由（`launch()` は再起動を挟みシミュレータが散発的に落ちる）
- 条件付き assert を書かない理由（要素が無いと何も検証せず緑になる）
- 呼出元によって dialog / snippet が出ないこと、`requestConfirmation` が UI から呼べないこと

引用は `[Apple: wwdc2026-345 16:30]` の形に揃えた（元は `（WWDC 2026 #345）` や
`（wwdc2022-10121 9:29）` が混在していた）。

## 判断として残すこと

- **`// MARK:` は英語にしたが残した**。構造のナビゲーションとして機能しているので、
  「コードの言い換え」には当たらない
- **`///` の API ドキュメントは減らしていない**。公開 API の契約は実装中に読む情報そのもの
- 逆に**削ってよかったと分かるのは「調査の記録がコメントに漏れていた」箇所**。
  `LiveActivityMonitor` の signature の説明が 5 行あったが、必要なのは
  「dueDate の無い todo は対象外なので観測しない」の 1 行だった
