# Xcode 27.2 正式版で App Intents 周りを測り直した件（#57）

現在の結論は [docs/APP_INTENTS_API_COVERAGE.md](../APP_INTENTS_API_COVERAGE.md) と
[skills/](../../skills/README.md) にある。ここには **27.2 正式版で何を測り、
[27.2 beta の記録](2026-09-25-xcode27.2-appintents-recheck.md)のどれが変わったか**を残す。
beta のときに「ビルドしないと分からない」と残した 4 項目もここで測った。

## 1. SDK 差分 — 比較元が残っていないので grep で確認した

旧版の Xcode を消していたので、前回の「sort してから diff」は取れなかった。
iOS の `AppIntents.swiftinterface` は 16,822 行（27.1 は 16,797 行）、`anyAppleOS 27.2` は 5 件（iOS / watchOS とも）。

**beta で見つけた 3 件のうち 1 件は正式版に入っていない**:

| 宣言 | 27.2 beta | 27.2 正式版 |
|---|---|---|
| `AssistantSchemaEnum.caseDisplayRepresentations` の既定実装 | `anyAppleOS 27.2` | **同じ形で入っている** |
| `@UnionValue` 用 `@Parameter` の `default:` / `size:` | `anyAppleOS 27.2` | **同じ形で入っている**（`IntentWidgetFamily` 版には `@available(tvOS, unavailable)`） |
| `AppIntentsTesting.DynamicPropertyPath.get(as:) async` | あった | **無い**。AppIntentsTesting に 27.2 の availability は 0 件。`DynamicPropertyPath` は同期の `as(_:)` と添字だけ |

**beta に無かった（と思われる）追加が 1 件**:

```swift
@available(anyAppleOS 27.2, *)
public init(importing: @escaping @Sendable (IntentValue) async throws -> Item)
```

`IntentValueRepresentation` の 2 つの extension（`where IntentValue : _SystemIntentValue` と
`where IntentValue == IntentPerson`）の両方に入った。27.1 までは `exporting:` を含む init しか無く、
**受け取るだけの `ValueRepresentation` が書けなかった**。beta の記録に無いので beta → 正式版の間の追加と
読んでいるが、比較元が無いので断定はしない。

**変わっていないもの**: `SystemShortcut` に公開 init は無い（`==` だけ）/ `IntentSystemContext` は
`preciseTimestamp` / `isVoiceOnly` / `locale` の 3 つ（2026-11-12 追記: これは struct 本体と 27.0 の extension だけを数えていた。
`anyAppleOS 26.0` の extension に `currentMode` があり、公開メンバは 4 つ。27.2 / 27.3 beta の swiftinterface で確認） / `AppEntityContext` は `.audio(_:)` だけ、
`AudioContext` は `.nowPlaying` だけ / `_ModelDelegationIntent` / `IntentResponseStream` は
`@_documentation(visibility: internal)` のまま。`WidgetKit` / `CoreSpotlight` / `VisualIntelligence` /
`_AppIntents_SwiftUI` / `ActivityKit` には 27.1 / 27.2 の availability が 0 件。

> **学び**: beta の SDK にあった宣言が正式版で消えることがある。beta で見つけた API を
> 「27.2 追加」と docs に書くときは、正式版で残っているかをもう一度見るまで仮のものとして扱う。
> 次の棚卸しに備えて、**旧版の swiftinterface はアプリを消す前にどこかへ退避しておく**と diff が取れる。

## 2. クリーンビルド

`-derivedDataPath` を一時ディレクトリにし、`CODE_SIGNING_ALLOWED=NO` で
iOS Simulator / watchOS Simulator / macOS / visionOS Simulator の 4 destination を回した。
**4 つとも BUILD SUCCEEDED、`warning:` / `error:` は 0**。iOS / watchOS で SSU が `archived 2 locales` を出した。

`inspect_appintents_metadata.py` は all clear。Intento.app に schema 14 件（action 8 / entity 4 / enum 2）、
`TodoAppEntity` は `reminders.ReminderEntity` で 20 プロパティ、App Shortcuts 8 件。watch は
「assistant schemas: none」。

このとき **スクリプトが macOS の `.app` をアプリとして認識していなかった**（メタデータが
`App.app/Contents/Resources/` にあるので、ラベルが `Resources` になる）。mac 側のチェックが黙って
飛んでいたので、ラベルの付け方を直した。

**schema 適合の要求**（必須パラメータ名・型）は、4 destination とも診断 0 で通ったので**変化なし**。

## 3. FB24548956（system value 型 `@Parameter` で SSU training が落ちる）— 27.2 で直った

`TodoAppShortcuts.swift` に一時的に `@Parameter var place: PlaceDescriptor?` を持つ Intent を足し、
App Shortcut に登録してクリーンビルドした。

- 生成される SSU 変数名が `GeoToolbox_PlaceDescriptorEntity` に変わった（beta までは
  ドット区切りの `GeoToolbox.PlaceDescriptorEntity` で、そのドットが正規表現エラーの原因だった）
- 正規表現エラーも `Could not archive` も出ず、`archived 2 locales`。en / ja の `nlu.appintents` が生成され、
  probe の発話も学習データに入っている

測っていないこと:

- `AddTodoIntent.location` 自体を `PlaceDescriptor` に戻す形は試していない（probe は別 Intent）
- **Xcode Cloud は 27.1 でビルドしている**。このバグはビルド時の SSU training で起きるので、
  配布ビルドの toolchain が 27.2 以上になるまでは、配布物はまだバグを踏む側にいる
- TestFlight で Siri の発話が通るか（AGENTS.md の 14 番。ローカルの生成物が正しいことは、
  配布物が読まれることを意味しない）

よって **AGENTS.md の 8 番は残し、「27.2 toolchain で直った / 配布ビルドが 27.2 になってから外す」と注記**した。
`AddTodoIntent.location` を `PlaceDescriptor` に戻すのは、Xcode Cloud が 27.2 になり、TestFlight で
確かめてからにする（#57）。

## 4. FB24570185（App Schema と watch ターゲットのメタデータ統合）— 直っていない

iOS アプリの `DependencyMetadataFileList` / `StaticMetadataFileList` には今も `Debug-watchsimulator` の
スライスが入っている。watch 側の型名を `TodoAppEntity` などに揃えた probe を作り、ビルドログにあった
`appintentsmetadataprocessor` の呼び出しをそのまま実行した:

| run | 結果 |
|---|---|
| control（今の型名のまま） | 正常。schema あり・20 プロパティ |
| 型名を衝突させる | `TodoAppEntity` / `CategoryAppEntity` / `TodoSectionAppEntity` が `schemas=[]`、`TodoAppEntity` は 10 プロパティ。`TodoListType` / `TodoLocationTriggerEvent` も schema を失う。watch に同名の型が無い `TodoLocationTriggerAppEntity` だけ無傷 |
| 入力順を逆にする | schema が残る（後勝ち） |

どの run も exit 0・警告 0 で、黙って壊れる。beta 6 と同じ挙動なので、**watch 用に別の型名を与える
今の回避策はそのまま必要**。

## 5. テスト（iPhone Duo / iOS 27.2 シミュレータ、署名あり）

342 件中 340 件 passed。DomainTests 19 / RepositoryTests 30 / TodoAppIntentsTests 187（`IntentExecutionTargetsTests`
4 件を含む）/ UITests 65 はすべて passed。`IntentTodoUITest` は 39 passed・2 failed で、AppIntentsTesting の
3 スイート（`TodoEntityQueryTests` / `TodoIntentExecutionTests` / `TodoSystemIntegrationTests`）は passed。

落ちた 2 件はどちらも XCUITest の画面操作（`testSearchTodos` の検索欄、`testNavigateToTodoDetail` の
戻るボタン）。iOS 27.2 の iPhone シミュレータが Duo しか無かったので画面形状のせいかもしれないが、
**原因は調べていない**。App Intents の話ではないので、この棚卸しの対象からは外した。
