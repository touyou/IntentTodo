## D. ❌ Liquid Glass 節の論理 — 指摘は取り下げ（本人の意図を記録する）

**2026-09-06 決着。D-1 / D-2 / D-3 はいずれも取り下げ。** こちらが `S45`–`S56` の主張を
**「透明化 → 役割が App Intents に移る」という因果**として読んで「飛躍がある」と指摘したが、
**本人の意図は別の構図だった**。

### D-0. ⭐ 本人の意図: 「保険」の構図

> コンテンツ重視なのは分かるけど、**それだけだとアクセシビリティを下げてまでやった意味が分からない**。
> でも、もし**それを下げてもいい保険があるなら理念を追い求めることができる** →
> **App Intents はその保険のひとつになっていた**

つまり主張は「透明にしたから App Intents が必要になった」（＝機能の移譲）ではなく、

```
Apple には理念（コンテンツ優先 / UI の存在感を下げる）がある
    ↓ 貫くと代償が出る（初期の Liquid Glass の AX 批判）
    ↓ 代償を許容できる「保険」があれば、それでも理念を追える
App Intents はその保険のひとつとして、すでに用意されていた
```

**「なぜ Apple はそこまでやれたのか」の説明**であって、因果の飛躍ではない。
`S52`「透明になった UI が担う役割はどこへ？」も、この構図の中では
「役割が消えるわけではない、受け皿がある」という問いとして機能している。

- `S54`（視覚的なタブが押せない人でも大丈夫）も `S46`–`S51`（AX 批判）も、**同じ「保険」の意図**で
  ああいう表現になっている。個別に「言い直したほうが安全」と言うのは、構図を壊す方向だった
- ⚠️ **観測として 1 つだけ残す**: 原稿を読まずスライドとノートだけを通しで読んだ 1 人（このレビュー）は、
  ここを**「役割の移譲」と読んだ**。**「保険」という言葉自体はスライドにもノートにも出てこない**ので、
  誤読の余地はある。ただし**会場では話し方と流れで補える範囲**という判断なので、変更は求めない
  （F の ⭐「アクセシビリティの代替に Siri、は乱暴では？」の答えは `99-script.notes.md` に控えてある）

## F. レビューのやり方（再現手順）

`.key` の中身は protobuf（`Index.zip`）なので直接は読めない。**AppleScript で 2 つ吸い出す**。

### F-1. 版面を見る（PDF 書き出し）

```bash
osascript -e 'tell application "Keynote" to export document 1 to POSIX file "/tmp/deck.pdf" as PDF ¬
  with properties {PDF image quality:Good, export style:IndividualSlides}'
```

- エージェントに読ませるなら PDF が一番早い（ページ単位で画像として読める）
- ⚠️ `skipped slides:false` を渡すとき、AppleScript 側の変数名に `skipped` を使うと
  `-10006` で落ちる（予約語衝突）

### F-2. 全文と発表者ノートを吸い出す（テキスト）

`text items of slide` と `presenter notes of slide` を全面ぶん回して 1 ファイルに落とす。
**ノートの字数が取れるので尺の逆算にも使える**（A-1）。

```applescript
tell application "Keynote"
	set d to document 1
	repeat with i from 1 to (count of slides of d)
		set s to slide i of d
		-- (object text of t) for each (text items of s), then (presenter notes of s)
	end repeat
end tell
```

- `default title item` / `default body item` はこのテンプレートでは空。**`text items` を回すのが正解**
- 書式は `font of object text of t` / `size of object text of t` で取れる。
  **単一の値が返れば書式が均一**なので、`object text` を丸ごと差し替えても書式が壊れない（C-1 の `S114`）

### F-3. 直すとき

- ⭐ **編集する前に、直す内容を出して本人の承認を取る**。誤字やコピペ残しのような機械的な
  誤りでも同じ（2026-09-06 の指摘）。**Keynote は本人の制作物で、こちらからは差分が見えない**
  （`.key` は git 管理外なので、何が変わったかを後から追えるのは本人だけ）
- **編集前に `ditto` でパッケージごとバックアップ**（`.key` はディレクトリパッケージ。約 95 MB）
- 文字列置換は **JXA**（`osascript -l JavaScript`）のほうが素直。`presenterNotes` / `objectText` に代入して
  `doc.save()`
- ⚠️ **Keynote 側でスマート置換が効いていると `--` が em dash に戻る**。C-1 の `S114` はこれが原因。
  直した後は必ず文字コードで確認する（`id of character` で U+002D = 45）
