## D. 論理の弱点（本編で 1 行潰すかの判断材料）

> `99-script.notes.md` C-2 で「Liquid Glass 節は現状位置のまま」と決定済み。**位置の話ではなく、
> 主張の繋ぎ方の話**として読んでほしい。F の ⭐「アクセシビリティの代替に Siri、は乱暴では？」と
> 隣接するが、そちらより射程が広い。

### D-1. 「透明化 → 役割が App Intents に移る」は因果が飛んでいる

`S50`–`S56` の流れ:「Apple は UI を透明化したかった」→「透明になった UI が担う役割はどこへ？」→
「App Intents である」→ `S56`「**補填どころか拡張してるとすら言える**」。

- 透明化は**視覚的な存在感を下げてコンテンツを優先する**話であって、**機能の移譲ではない**。
  ここを因果で繋ぐと「透明にしたから App Intents が要る」に聞こえ、反論の的が立つ
- ⭐ **「同じ方向を向いた 2 つの動き」として並べれば、考察としての面白さは保ったまま反論を受けない**。
  「UI の存在感を下げる動きと、UI を経由しない到達経路を増やす動きが、同じ数年間に並行して起きている」
- **`S117`–`S118` でこの仮説に戻ると、飛躍が「問い」として回収される**
  （`99-script.notes.md` D-6 / B-2 で未反映と判明したぶん）。30 秒

### D-2. `S54` は AX に詳しい人に刺される

「App Intents は Siri に対応している。だからタブを開きたい時、タブを開いてというだけで開ける。
**視覚的なタブが押せない人でも大丈夫です**」。

- B-5 の改稿で「App Intents なら自動でそうなる」問題は解消済み。**残っているのは論点のすり替え**:
  Liquid Glass の**コントラスト**批判に **Siri** を答えとして出している。Siri は代替経路であって、
  透明な UI のコントラスト不足の解決ではない（VoiceOver / Dynamic Type の話とも別）
- ⭐ **「App Intents はアクセシビリティ対応の代替ではなく、到達経路の追加」と 1 回明言してから進む**。
  `99-script.notes.md` B-0x の「操作経路が 1 本増える」に寄せる案と同じ結論

### D-3. `S46`–`S51` は「その後調整された」に触れておく

「Apple 自身が Accessibility を中心の理念と表現しているのに、初期の Liquid Glass は批判を浴びた」という
流れ。その後の調整に触れているのは `S51` のノートだけ（B-4 の改稿ぶん）。
**2026 年 9 月の話として、面の上にも 1 行あると古く見えない**。

## F. レビューのやり方（再現手順）

`.key` の中身は protobuf（`Index.zip`）なので直接は読めない。**AppleScript で 2 つ吸い出す**。

### F-1. 版面を見る（PDF 書き出し）

```bash
osascript -e 'tell application "Keynote" to export document 1 to POSIX file "/tmp/deck.pdf" as PDF ¬
  with properties {PDF image quality:Good, export style:IndividualSlides}'
```

- エージェントに読ませるなら PDF が一番早い（ページ単位で画像として読める）
- ⚠️ `skipped slides:false` を渡すとき、AppleScript 側の変数名に `skipped` を使うと
  `-10006` で落ちる（予約語衝突）

### F-2. 全文と発表者ノートを吸い出す（テキスト）

`text items of slide` と `presenter notes of slide` を全面ぶん回して 1 ファイルに落とす。
**ノートの字数が取れるので尺の逆算にも使える**（A-1）。

```applescript
tell application "Keynote"
	set d to document 1
	repeat with i from 1 to (count of slides of d)
		set s to slide i of d
		-- (object text of t) for each (text items of s), then (presenter notes of s)
	end repeat
end tell
```

- `default title item` / `default body item` はこのテンプレートでは空。**`text items` を回すのが正解**
- 書式は `font of object text of t` / `size of object text of t` で取れる。
  **単一の値が返れば書式が均一**なので、`object text` を丸ごと差し替えても書式が壊れない（C-1 の `S114`）

### F-3. 直すとき

- **編集前に `ditto` でパッケージごとバックアップ**（`.key` はディレクトリパッケージ。約 95 MB）
- 文字列置換は **JXA**（`osascript -l JavaScript`）のほうが素直。`presenterNotes` / `objectText` に代入して
  `doc.save()`
- ⚠️ **Keynote 側でスマート置換が効いていると `--` が em dash に戻る**。C-1 の `S114` はこれが原因。
  直した後は必ず文字コードで確認する（`id of character` で U+002D = 45）
